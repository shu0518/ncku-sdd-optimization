# `fc` Flashcard CLI Tool — v2.0 產品需求文件

**文件版本：** 2.0.0-PRD | **發佈日期：** 2026-03-16

---

## 背景說明

自 v1.0 上線以來，使用者回饋集中於以下幾個痛點：

**首先，複習體驗缺乏學習回饋。** 目前 `review` 指令結束後僅顯示「複習了幾張卡」，使用者完全無法得知自己的記憶狀況是否在進步、哪些卡片是長期弱點。這讓「複習」變成了機械性的動作，而非真正有效的學習循環。

**其次，複習邏輯不夠聰明。** v1.0 採用隨機抽卡（`RandomReviewStrategy`），無論某張卡昨天剛複習過、還是三週沒碰過，每次都以相同機率被選中。這違背了間隔重複（Spaced Repetition）的核心精神——應該把有限的複習時間優先分配給「最需要被複習」的卡片。

**第三，卡片管理缺乏彈性。** 一旦卡片建立，使用者只能刪除後重新新增才能更正錯字或補充說明，操作成本過高。

為了解決以上問題，v2.0 將在 **不破壞任何 v1.0 已定義測試案例** 的前提下，進行以下延伸。v1.0 已經預先保留了 `next_review_date`、`repetitions`、`ease_factor`、`interval` 等 SM-2 欄位，以及 `strategy.py` 的策略模式介面，v2.0 將正式啟用這些設計。

## 需求列表

### 需求一：啟用 SM-2 間隔重複演算法（修改既有模組）

**涉及模組：** `strategy.py`、`storage.py`、`models.py`

v1.0 在 `strategy.py` 中預留了 `SM2ReviewStrategy` 的擴充位置，v2.0 需要正式實作此策略，並讓 `fc review` 預設採用它（取代原本的 `RandomReviewStrategy`）。

**核心行為：**

- 每次複習後，程式須根據使用者輸入的評分（1–5）更新該張卡片的 `repetitions`、`ease_factor`、`interval`，並計算出新的 `next_review_date`，寫回 `cards.json`。SM-2 演算法的計算規則可參考公開文獻，學生須自行判斷如何對應評分值與 SM-2 的品質參數（q 值）之間的關係。

- `fc review` 在選卡時，應優先選取 **今天到期（`next_review_date` ≤ 今日）** 或 **從未複習過（`next_review_date` 為 null）** 的卡片，而非隨機選取全部卡片。

- `--limit` 選項的語意維持不變：限制本次複習的最大張數。

**注意事項：** `RandomReviewStrategy` 不得被刪除，主程式應提供某種方式讓使用者在需要時仍能選擇隨機模式（具體機制由學生自行設計，例如新增 CLI 選項）。

---

### 需求二：新增 `fc edit` 字卡編輯指令（全新功能）

使用者需要能夠修正既有字卡的正面、背面或所屬牌組，而不必刪除後重建。

**基本行為：**

```
fc edit --id <UUID> [--front TEXT] [--back TEXT] [--deck TEXT]
```

- `--id` 為必填，其餘三個選項至少需提供一個；若三者皆未提供，程式應提示使用者至少指定一個要修改的欄位，並以 Exit Code `2` 結束。

- 成功修改後輸出：`✓ Card <id> updated.`

- 若指定的 ID 不存在，行為與 `fc delete` 一致（輸出錯誤至 stderr，Exit Code `1`）。

- `edit` 指令 **不應重置** 卡片的 SM-2 相關欄位（`repetitions`、`ease_factor`、`interval`、`next_review_date`），除非學生有充分理由並在設計文件中說明。

---

### 需求三：複習結束後顯示場次統計摘要（修改既有模組）

**涉及模組：** `main.py`（`cmd_review`）

目前複習結束的摘要訊息僅有一行 `Session complete. Reviewed: N cards.`，資訊量不足。v2.0 應在這行訊息之後，額外輸出本次場次的統計資訊。

**可觀察行為（以使用者視角描述）：**

複習結束後，使用者應能看到：
- 本次各評分等級（1–5）的分佈情況（例如：幾張得了 1 分、幾張得了 5 分）
- 本次場次的**平均評分**，四捨五入至小數點後一位

具體的輸出格式與排版由學生自行設計，但需保留原有的 `Session complete. Reviewed: N cards.` 作為第一行，統計資訊附加於其後。

**邊界情境：** 若本次複習了 0 張卡（例如 `--limit 0` 或無到期卡片），則不輸出統計資訊，僅顯示原有的摘要行，行為與 v1.0 完全相同。

---

### 需求四：新增 `fc stats` 全域統計指令（全新功能）

使用者需要一個整體視角，了解自己在各牌組的學習狀況，以便規劃接下來的複習計畫。

**基本行為：**

```
fc stats [--deck TEXT]
```

- 不指定 `--deck` 時，輸出**所有牌組**的統計資訊。
- 指定 `--deck` 時，僅輸出該牌組的統計資訊。

每個牌組應呈現以下可觀察的資訊（欄位名稱與格式由學生自行設計）：

| 資訊類型 | 說明 |
|----------|------|
| 牌組名稱 | 該牌組的識別名稱 |
| 卡片總數 | 該牌組共有幾張卡 |
| 今日到期數 | `next_review_date` ≤ 今日（含從未複習過的卡片）的數量 |
| 平均熟悉度 | 該牌組所有卡片 `ease_factor` 的平均值，反映整體記憶穩定性 |

- 若資料庫中無任何卡片，輸出 `No stats available.` 並以 Exit Code `0` 結束。
- `fc stats` 為唯讀操作，不應修改任何卡片資料。

## 驗收標準

以下以**使用者可觀察的行為**描述各需求的最低驗收條件：

**SM-2 演算法（需求一）**

1. 對同一張卡片連續給予高評分（4 或 5）複習三次後，執行 `fc stats`，可觀察到該卡片的 `next_review_date` 每次都比前一次間隔更長（間隔天數遞增）。
2. 對某張卡片給予低評分（1 或 2）後，該卡片的下次複習日期被重設為近期，在下一次 `fc review` 時仍會出現（而非被推遲）。
3. v1.0 的 T04、T07、T08、T10 測試案例行為不變。

**字卡編輯（需求二）**

4. 執行 `fc edit --id <uuid> --front "新問題"` 後，立即執行 `fc list`，對應卡片的正面文字已更新為「新問題」。
5. 執行 `fc edit --id <不存在的UUID> --front "X"` 後，stderr 輸出包含 `not found`，Exit Code 為 `1`。
6. 執行 `fc edit --id <uuid>`（未提供任何修改欄位），程式不靜默結束，而是輸出提示訊息並以非零 Exit Code 結束。

**場次統計摘要（需求三）**

7. 完成一次包含 5 張卡片的複習後，輸出的第一行仍為 `Session complete. Reviewed: 5 cards.`，其後附有評分分佈與平均分數。
8. 執行 `fc review --limit 0` 時，輸出行為與 v1.0 完全相同（僅一行 `Session complete. Reviewed: 0 cards.`，無統計資訊）。

**全域統計（需求四）**

9. 在有卡片的狀態下執行 `fc stats`，輸出中可識別各牌組名稱、卡片數量，以及今日到期（需複習）的卡片數量。
10. 執行 `fc stats` 不會改變 `cards.json` 的內容（可在執行前後比較檔案雜湊值或時間戳）。
11. 資料庫為空時，`fc stats` 輸出 `No stats available.`，Exit Code 為 `0`。
